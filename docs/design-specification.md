# Student Game Gallery 設計仕様書

## 1. 文書情報

| 項目 | 内容 |
|---|---|
| サイト名称 | Student Game Gallery（仮称） |
| 文書版数 | 0.7 |
| サイト種別 | 学生ゲーム作品の成果展示サイト |
| 公開基盤 | GitHub Pages |

## 2. 目的

授業で制作された複数のPC向けゲームを紹介し、各作品と学生の制作成果に対する認知を広げる。作品の概要や特徴、画像などを閲覧できるようにし、希望者がGoogle Driveからゲーム本体をダウンロードできる場を提供する。

## 3. 想定閲覧者

- 学生作品に関心のある一般来場者
- 学生
- 教職員
- ゲーム制作や教育成果に関心のある閲覧者

## 4. 基本方針

- 複数のゲームを一覧性の高いカード形式で紹介する。
- 各作品の概要と特徴を個別の詳細画面で分かりやすく伝える。
- 明るく親しみやすいデザインとしつつ、授業成果展示としての見やすさと信頼感を保つ。
- PC、タブレット、スマートフォンで利用できるレスポンシブデザインとする。
- サーバー側プログラムを使用しない静的サイトとして構築し、GitHub Pagesで公開する。
- 作品情報はGoogleスプレッドシートで入力・管理し、検証済みのJSONへ変換して公開する。
- 作品の追加や更新は、スプレッドシートの編集、JSONへの変換、画像ファイルの追加または差し替えで行えるようにする。

## 5. 公開情報と個人情報

制作者情報として公開する項目は次の3点に限定する。

- チーム名
- 学年
- 制作年度

以下の情報は掲載しない。

- 学生の氏名
- 学籍番号
- 個人の連絡先
- 学校名
- 学科名
- 授業名

公開前に、スクリーンショットや動画、説明文、ゲーム内表示に個人情報が含まれていないことを確認する。

## 6. サイト構成

### 6.1 トップページ

- ヘッダーにテキストで表示するサイト名
- ピックアップ作品
- 新着作品
- ゲーム作品一覧の一部
- ゲーム一覧への導線
- ダウンロード時の注意事項への導線

独立したロゴ、キャッチコピー、大型のメインビジュアルは設けない。ページ上部から作品画像と作品情報を表示し、作品紹介を主役とする。

### 6.2 ゲーム一覧

- ゲームカード一覧
- キーワード検索
- ジャンルによる絞り込み
- 制作年度による絞り込み
- 検索・絞り込み条件のリセット
- 条件に一致する件数の表示
- 該当作品がない場合の案内

ゲームカードには、原則として次の情報を表示する。

- サムネイル
- ゲームタイトル
- 短い紹介文
- ジャンル
- チーム名
- 学年
- 制作年度
- 詳細画面へのリンク

### 6.3 ゲーム詳細

- ゲームタイトル
- メインビジュアル
- スクリーンショット
- ゲーム概要
- ゲームの特徴
- ジャンル
- プレイ人数
- 想定プレイ時間
- 操作方法
- 対応OSおよび動作環境
- チーム名
- 学年
- 制作年度
- ゲームバージョン
- ダウンロードファイル容量
- 更新日
- 紹介動画（任意）
- Google Driveへのダウンロードボタン
- 起動方法
- 注意事項

### 6.4 サイトについて

- サイトの目的
- 掲載作品が学生の授業成果であることの説明
- 掲載情報と個人情報に関する方針

### 6.5 ダウンロード時の注意事項

- 配布形式と展開方法
- ゲームの起動方法
- 対応OSの確認方法
- Windowsの警告が表示される場合の案内
- 外部サイトであるGoogle Driveへ移動することの説明
- ダウンロードおよび実行を利用者自身の判断で行う旨

## 7. 検索・絞り込み仕様

### 7.1 キーワード検索

検索対象は以下とする。

- ゲームタイトル
- 短い紹介文
- ゲーム概要
- チーム名

文字入力に応じて、ブラウザ上で検索結果を更新する。

### 7.2 絞り込み

- ジャンルを1つ選択して絞り込める。
- 制作年度を1つ選択して絞り込める。
- キーワード、ジャンル、制作年度は組み合わせて利用できる。
- リセット操作ですべての条件を初期状態に戻せる。

### 7.3 表示順

- 初期表示は制作年度の新しい順とする。
- 同じ制作年度の作品は、データファイル内の掲載順を使用する。

## 8. ダウンロード仕様

- ゲーム本体はGoogle Driveに保存する。
- サイト上のダウンロードボタンからGoogle Driveの共有リンクを開く。
- リンク先が外部サイトであることをボタン付近に明示する。
- 共有権限は、原則として「リンクを知っている全員が閲覧可能」とする。
- ゲームファイルは原則ZIP形式とする。
- ボタン付近に対応OS、バージョン、容量、更新日を表示する。
- 配布前にウイルスチェックを行い、確認状況を表示できるようにする。
- Google Drive上のファイル更新時は、可能な限り共有URLを維持する。
- 公開時および更新時にリンク切れと共有権限を確認する。

## 9. データ管理

### 9.1 管理方式

Googleスプレッドシートを作品情報の入力・編集画面として使用し、JSONをWebサイトの公開用データとして使用する。WebサイトからGoogleスプレッドシートを直接参照せず、変換時に入力内容を検証したうえで、リポジトリ内のJSONを更新する。

```text
Googleスプレッドシートで入力・編集
              ↓
     入力内容の検証・変換
              ↓
       games.jsonを生成
              ↓
       GitHubへ反映
              ↓
 GitHub PagesがJSONを読み込む
```

この構成により、入力担当者はスプレッドシート上で編集でき、公開サイトはGoogle側の通信状況や共有設定に依存せずに表示できる。

想定構成：

```text
data/
  games.json
assets/
  games/
    game-id/
      thumbnail.webp
      main.webp
      screenshot-01.webp
      screenshot-02.webp
```

### 9.2 主なデータ項目

| 項目 | 必須 | 内容 |
|---|---:|---|
| `id` | 必須 | URLや画像フォルダーに使用する重複しない識別子 |
| `title` | 必須 | ゲームタイトル |
| `summary` | 必須 | 一覧用の短い紹介文 |
| `description` | 必須 | 詳細画面用の概要 |
| `features` | 必須 | 特徴の配列 |
| `genre` | 必須 | ジャンル |
| `players` | 必須 | プレイ人数 |
| `playTime` | 任意 | 想定プレイ時間 |
| `controls` | 必須 | 操作方法の配列 |
| `supportedOs` | 必須 | 対応OSの配列 |
| `systemRequirements` | 任意 | その他の動作環境 |
| `teamName` | 必須 | チーム名 |
| `grade` | 必須 | 学年 |
| `productionYear` | 必須 | 制作年度 |
| `version` | 必須 | ゲームのバージョン |
| `fileSize` | 必須 | ダウンロード容量 |
| `updatedAt` | 必須 | 更新日 |
| `downloadUrl` | 必須 | Google Drive共有URL |
| `videoUrl` | 任意 | 紹介動画URL |
| `thumbnail` | 必須 | 一覧用画像 |
| `mainImage` | 必須 | メイン画像 |
| `screenshots` | 任意 | スクリーンショットの配列 |
| `launchInstructions` | 必須 | 起動方法 |
| `notes` | 任意 | 注意事項 |
| `virusCheckedAt` | 任意 | ウイルスチェック実施日 |
| `pickup` | 任意 | ピックアップ対象として掲載するか |
| `pickupOrder` | 任意 | ピックアップ内の表示順（1～3） |
| `pickupStartDate` | 任意 | ピックアップ掲載開始日 |
| `pickupEndDate` | 任意 | ピックアップ掲載終了日 |

### 9.3 データ規則

- `id`は半角英小文字、数字、ハイフンのみを使用する。
- `id`は作品間で重複させない。
- 日付は`YYYY-MM-DD`形式とする。
- 制作年度は西暦4桁の数値とする。
- URLは`https://`から始まるものに限定する。
- 必須項目が不足する作品は公開対象にしない。

### 9.4 Googleスプレッドシート仕様

- 1作品を1行で管理する。
- 1行目を項目名として固定する。
- 必須項目と任意項目を区別する。
- ジャンル、学年、対応OSなど、選択肢を限定できる項目には入力規則を設定する。
- 制作年度は西暦4桁、更新日は日付として入力する。
- 複数の値を持つ項目は、所定の区切り文字または別シートで管理し、変換方法を統一する。
- `id`の重複、必須項目の空欄、不正なURL、不正な日付を確認できる検証欄を設ける。
- 公開対象かどうかを指定する列を設け、下書きの作品をJSONへ含めないようにする。
- スプレッドシートの共有範囲は入力担当者に限定し、Web公開を必須としない。
- ピックアップ運用のため、`lastPickupDate`、`rightsChecked`、`downloadCheckedAt`を管理用項目として設ける。
- 管理用項目は、Webサイトでの表示に不要な場合は公開JSONへ出力しない。

### 9.5 JSON変換仕様

- Googleスプレッドシートに紐づけたGoogle Apps Script（GAS）で変換処理を実装する。
- スプレッドシートを開いたとき、専用メニュー「作品データ」を表示する。
- 専用メニューには「入力内容を検証」と「公開用JSONを出力」を設ける。
- 変換処理はスプレッドシートの列名をJSONの項目名へ対応付ける。
- 公開対象として設定された行のみを出力する。
- 変換前に必須項目、データ型、日付、URL、`id`の重複を検証する。
- 検証エラーが1件でもある場合はJSONを生成せず、ダウンロードを開始しない。
- エラー時は、対象行、対象項目、理由をダイアログに一覧表示する。
- 必要に応じて、エラーのあるセルを識別できる表示を行う。
- 正常終了時は、UTF-8形式の`games.json`を生成する。
- JSON文字列をGASのHTMLダイアログへ渡し、ブラウザから手動ダウンロードできるようにする。
- GASを外部向けWebアプリとして公開せず、スプレッドシートの編集者だけが実行する。
- JSONの項目順と配列の扱いを一定にし、Git上で変更箇所を確認しやすくする。
- ダウンロードした`games.json`で、リポジトリ内の`data/games.json`を手動更新する。
- 更新後のJSONはGitで履歴管理し、問題が発生した場合に以前の状態へ戻せるようにする。

### 9.6 GASの権限と管理

- GASは対象のGoogleスプレッドシートに紐づくコンテナバインドスクリプトとして作成する。
- 初回実行時は、実行者がGoogleの権限確認を完了する必要がある。
- スプレッドシートとGASの編集権限は、運用担当者だけに付与する。
- GASにGitHubの認証情報やその他の秘密情報を保存しない。
- GASのソースコードは、スプレッドシート内だけでなくリポジトリにも複製して履歴管理する。
- JSON出力の操作はPCのWebブラウザで行うことを基本とする。

### 9.7 更新手順

1. 入力担当者がGoogleスプレッドシートへ作品情報を入力する。
2. 画像担当者が所定のフォルダーへ画像を配置する。
3. スプレッドシートの「作品データ」メニューから「入力内容を検証」を実行する。
4. 検証エラーがある場合はスプレッドシートを修正し、再度検証する。
5. 「公開用JSONを出力」を実行し、`games.json`をダウンロードする。
6. リポジトリ内の`data/games.json`をダウンロードしたファイルで更新する。
7. JSONの変更差分を確認する。
8. 生成されたJSONと画像をローカルのプレビュー環境で確認する。
9. GitHubへ反映し、GitHub Pagesを更新する。
10. 公開ページとGoogle Driveのダウンロードリンクを確認する。

## 10. デザイン仕様

### 10.1 トーン

- 明るい
- 親しみやすい
- 活気がある
- 学生作品の多様性を邪魔しない
- 子ども向けに偏りすぎず、成果展示として信頼できる

### 10.2 表現方針

- ペールブルーをページ背景、白をカード背景に使用する。
- ブライトブルーを主要ボタン、リンク、選択状態に使用する。
- サンイエローはピックアップ作品、新着ラベルなどの限定的な強調に使用する。
- カードやボタンには適度な角丸を使用する。
- 作品画像を大きく扱い、作品ごとの個性が伝わる構成にする。
- 過度なアニメーションを避け、操作の反応を伝える程度の動きを使用する。
- 本文と背景には十分なコントラストを確保する。

### 10.3 配色

| 用途 | 色名 | カラーコード |
|---|---|---|
| メインカラー | ブライトブルー | `#2563EB` |
| メインカラーのホバー | ディープブルー | `#1D4ED8` |
| アクセントカラー | サンイエロー | `#F59E0B` |
| ページ背景 | ペールブルー | `#F5FAFF` |
| カード背景 | ホワイト | `#FFFFFF` |
| 見出し・本文 | ネイビーブルー | `#183153` |
| 補助テキスト | スレートブルー | `#5D6F87` |
| 境界線 | ライトブルーグレー | `#DCE9F7` |
| 淡い強調背景 | ソフトブルー | `#EAF2FF` |
| 成功・公開済み | グリーン | `#15803D` |
| 警告 | ダークオレンジ | `#C2410C` |
| エラー | レッド | `#B91C1C` |

配色はCSSカスタムプロパティで一元管理する。主要な操作ボタンとダウンロードボタンはブライトブルーを使用し、サンイエローを主要操作色として使用しない。状態を示す場合は色だけに依存せず、文字またはアイコンを併用する。

### 10.4 フォント

- 見出しには`M PLUS Rounded 1c`を使用する。
- 本文、ナビゲーション、ボタン、フォームには`Noto Sans JP`を使用する。
- Google FontsからWebフォントを読み込む。
- Webフォントを読み込めない場合は、`Yu Gothic`、`Meiryo`、`sans-serif`の順で代替する。
- ゲーム画像内のロゴ表現を除き、Webページ上の文字は指定フォントへ統一する。

```css
:root {
  --font-heading: "M PLUS Rounded 1c", "Yu Gothic", sans-serif;
  --font-body: "Noto Sans JP", "Yu Gothic", "Meiryo", sans-serif;
}
```

読み込むウェイトは、`M PLUS Rounded 1c`の700と800、`Noto Sans JP`の400、500、700を基本とする。

### 10.5 文字サイズ

| 用途 | PC | スマートフォン |
|---|---:|---:|
| ページタイトル | 48px | 32px |
| セクション見出し | 28px | 24px |
| カードタイトル | 20px | 18px |
| 本文 | 16px | 16px |
| 補助テキスト | 14px | 14px |
| ラベル | 13px | 13px |
| ボタン | 16px | 16px |

- 本文の行間は原則`1.7`とする。
- 本文のフォントウェイトは400を基本とする。
- ボタンと小見出しは700、大見出しは700または800とする。
- 重要な本文を14px未満にしない。

### 10.6 角丸と影

- ゲームカードの角丸は18pxを基本とする。
- ボタンは用途に応じて12pxまたは円形に近い角丸を使用する。
- 入力欄と選択欄の角丸は12pxを基本とする。
- 影はカードを背景から識別するための淡い表現に限定する。
- ホバー時に大きく移動または拡大する表現は使用しない。

### 10.7 ロゴとページ上部

- 独立したシンボルロゴおよび画像ロゴは作成しない。
- ヘッダーにはサイト名`Student Game Gallery`をテキストで簡潔に表示する。
- サイト名には見出し用フォントを使用し、装飾を抑える。
- キャッチコピーは掲載しない。
- 大型のヒーロー画像や装飾中心のメインビジュアルは設けない。
- ページ上部の占有面積を抑え、初期表示の範囲に作品画像または作品カードが入るようにする。
- サイト共通の装飾よりも、各作品のサムネイルとスクリーンショットを視覚的な主役とする。
- サイトの目的説明が必要な場合は、作品一覧を妨げない短い文章として掲載する。

### 10.8 トップページの優先順位

トップページの情報は、原則として次の優先順位で配置する。

1. ピックアップ作品または新着作品
2. 作品のサムネイル、タイトル、概要
3. ゲーム一覧と検索への導線
4. サイトについての短い説明
5. ダウンロード時の注意事項への導線

### 10.9 ピックアップ作品の表示

- セクション名は「ピックアップ作品」とする。
- トップページへ3作品を同じ大きさのカードで表示する。
- ランキング番号、順位、優秀作品など、評価と受け取られる表現を使用しない。
- ピックアップであることは短い見出しまたはラベルで示し、過度に装飾しない。
- PCでは3列、スマートフォンでは1列で表示する。
- 対象作品がない場合は、ピックアップセクション自体を表示しない。
- 各カードから作品詳細ページへ移動できるようにする。

### 10.10 ピックアップ作品の選定・運用

ピックアップは作品の評価や成績を示すものではなく、作品を順番に紹介するためのローテーション枠とする。

### 掲載条件

以下をすべて満たす作品を候補とする。

- 作品が公開対象に設定されている。
- 必須情報がすべて入力されている。
- サムネイルとメイン画像が登録されている。
- Google Driveのダウンロードリンクが正常である。
- 対応OS、容量、バージョン、起動方法が記載されている。
- 個人情報および権利上の問題がないことを確認済みである。
- ゲームファイルのウイルスチェックが完了している。

### 選定ルール

- ゲームの完成度、成績、人気による順位付けは行わない。
- ジャンルが偏らないようにする。
- 同じチームの作品を同時に複数掲載しない。
- 直近の期間に掲載されていない作品を優先する。
- 新規作品だけに固定せず、過去年度の作品も対象にする。
- 条件が同じ場合は、担当者が掲載履歴を確認してローテーションを設定する。

### 更新ルール

- 原則として月1回、またはサイト更新時に入れ替える。
- 学期または年度の切り替わり時に掲載内容を見直す。
- ダウンロードリンクや公開内容に問題が発生した作品は、一時的に掲載対象から外す。
- 掲載履歴をGoogleスプレッドシートで管理し、特定作品への偏りを防ぐ。

## 11. レスポンシブ対応

- PCでは複数列のゲームカードを表示する。
- タブレットでは画面幅に応じて列数を減らす。
- スマートフォンでは原則1列表示とする。
- タッチ操作でも押しやすいボタンサイズを確保する。
- 横スクロールを発生させない。
- 画像は画面幅に応じて縮小する。

## 12. アクセシビリティ

- 画像には内容を表す代替テキストを設定する。
- キーボードのみでも主要機能を操作できるようにする。
- フォーカス位置を視覚的に確認できるようにする。
- 色だけに依存して状態や情報を伝えない。
- 見出し階層を適切に設定する。
- フォーム部品にはラベルを設定する。
- 動画を自動再生しない。

## 13. 技術方針

### 13.1 フロントエンド技術

- HTML、CSS、JavaScriptのみを使用する。
- React、Vue、Astroなどのフロントエンドフレームワークは使用しない。
- TypeScript、CSSプリプロセッサー、CSSフレームワークは初期構成では使用しない。
- JavaScriptはブラウザが直接実行できるES Modulesとして構成する。
- 共通の配色、余白、文字サイズ、角丸などはCSSカスタムプロパティで管理する。
- 機能ごとにJavaScriptファイルを分割し、1つのファイルへ処理を集中させない。

### 13.2 ビルド方式

- フロントエンドのバンドルやコンパイルは行わない。
- HTML、CSS、JavaScript、JSON、画像を静的ファイルとしてGitHub Pagesへ配置する。
- ローカル確認では静的ファイルを配信できるローカルWebサーバーを使用する。
- GitHub Actionsでは、データ検証と静的ファイルの公開を行う。
- GoogleスプレッドシートからJSONへの変換処理は、スプレッドシートに紐づけたGASとして実装し、Webサイト本体とは分離する。

### 13.3 画面生成

- 検索、絞り込み、ゲームカード生成、詳細表示はブラウザ側のJavaScriptで処理する。
- ゲーム情報は`data/games.json`から`fetch`で取得する。
- 詳細画面は共通のHTMLを使用し、URLクエリの作品IDを基に対象データを表示する。
- 詳細画面のURL形式は、初期仕様では`game.html?id=game-id`とする。
- 存在しない作品IDが指定された場合は、作品が見つからない旨と一覧へ戻る導線を表示する。
- JavaScriptやJSONの読み込みに失敗した場合は、利用者向けのエラーメッセージを表示する。

### 13.4 GitHub Pages対応

- GitHub Pagesで公開可能な静的サイトとして構築する。
- プロジェクトサイト配下でもパスが崩れないよう、相対パスを基本とする。
- 大文字と小文字を区別してファイル名と参照先を統一する。
- 外部リンクには安全なリンク属性を設定する。
- 秘密情報、Google APIの認証情報、APIキーをリポジトリへ保存しない。
- Googleスプレッドシートを公開サイトから直接読み込まない。

### 13.6 将来の移行

作品数や機能が増え、HTML、CSS、JavaScriptのみでの保守が難しくなった場合は、静的サイトジェネレーターやフロントエンドフレームワークの導入を再検討する。JSONのデータ構造とURL設計を可能な限り維持し、移行範囲を小さくする。

## 14. 品質・運用要件

- 公開前にPCとスマートフォンの主要ブラウザで表示確認を行う。
- ゲーム追加時にデータ形式、画像、ダウンロードリンクを確認する。
- スプレッドシートからJSONへ変換する際に入力検証を行う。
- 公開前に生成されたJSONの差分を確認する。
- 画像はWeb表示向けに圧縮し、原則WebP形式を使用する。
- サムネイル画像の縦横比を統一する。
- Google Driveの共有リンクと権限を定期的に確認する。
- 公開済み作品を削除する場合は、リンク切れページを残さない。

### 14.1 対応ブラウザ

特定のバージョン番号へ固定せず、原則として次の範囲を対象とする。

| 環境 | 対応範囲 | 優先度 |
|---|---|---|
| Windows版Google Chrome | 最新版と1つ前のメジャーバージョン | 最優先 |
| Windows版Microsoft Edge | 最新版と1つ前のメジャーバージョン | 最優先 |
| Mozilla Firefox | 最新版と1つ前のメジャーバージョン | 標準対応 |
| macOS版Safari | 最新版と1つ前のメジャーバージョン | 標準対応 |
| iOS／iPadOS Safari | 最新OSと1つ前のOS | 標準対応 |
| Android版Google Chrome | 最新版と1つ前のメジャーバージョン | 標準対応 |

- Internet Explorerは対応対象外とする。
- 実験的なWeb APIに依存しない。
- 対象ブラウザで使用できない機能には、代替表示または安全な縮退動作を用意する。

### 14.2 基準テスト環境

- Windows 11 + Google Chrome
- Windows 11 + Microsoft Edge
- Windows 11 + Mozilla Firefox
- macOS + Safari
- iPhone相当の表示環境
- Androidスマートフォン相当の表示環境

実機を用意できない場合はブラウザの開発者ツールで代替できるが、公開前には可能な範囲で実機確認を行う。

### 14.3 代表画面幅

| 用途 | 確認幅 |
|---|---:|
| 小型スマートフォン | 320px |
| 標準スマートフォン | 375px |
| 大型スマートフォン | 430px |
| タブレット | 768px |
| 小型PC | 1024px |
| 標準PC | 1440px |

320px以上の画面幅で、ページ全体に意図しない横スクロールが発生しないことを必須とする。

### 14.4 機能テスト

#### 基本表示

- HTML、CSS、JavaScript、JSON、画像が正常に読み込まれる。
- GitHub Pagesのプロジェクトサイト配下でもパスが崩れない。
- Webフォント未読込時も代替フォントで閲覧できる。
- 画像の縦横比が崩れない。
- 長いタイトルやチーム名でもレイアウトが崩れない。
- JavaScriptの読み込みに失敗した場合に案内を表示する。

#### ゲーム一覧

- JSONからすべての公開作品を読み込める。
- 非公開作品を表示しない。
- キーワード検索、ジャンル、制作年度の絞り込みが機能する。
- 複数条件を組み合わせられる。
- 条件のリセットと検索件数の表示が正しく機能する。
- 該当作品がない場合に案内を表示する。

#### ゲーム詳細

- URLの作品IDに対応する作品を表示する。
- 存在しないIDの場合にエラー表示と一覧への導線を表示する。
- 概要、画像、操作方法、動作環境などを正しく表示する。
- 任意項目が空の場合に不要な見出しや空白を残さない。
- Google Driveのダウンロードリンクを新しいタブで開く。
- 外部サイトへ移動することを明示する。

#### ピックアップ作品

- 対象となる3作品を表示する。
- `pickupOrder`の順番を反映する。
- 掲載期間外の作品を表示しない。
- 対象作品がない場合はセクションを非表示にする。
- 4作品以上が指定された場合はGASの検証エラーとする。

### 14.5 レスポンシブ・アクセシビリティテスト

- PCではカードを複数列、スマートフォンでは1列で表示する。
- ナビゲーション、検索欄、ボタンが画面外へ出ない。
- タッチ対象に十分な大きさを確保する。
- 端末の縦向きと横向きで表示が崩れない。
- キーボードのみで主要機能を操作できる。
- フォーカス位置を視覚的に確認できる。
- 画像に代替テキストが設定されている。
- フォーム部品にラベルが設定されている。
- 見出し階層が正しい。
- 色だけに依存して状態を伝えていない。
- 200%拡大でも主要機能を利用できる。
- `prefers-reduced-motion`を尊重する。

### 14.6 テスト実施方針

- GASで入力データの検証を自動化する。
- 検索、絞り込み、日付判定などの副作用を持たないJavaScript処理には単体テストを用意する。
- HTMLの構文チェックを実施する。
- GitHub ActionsでJSON検証と必須ファイルの存在確認を行う。
- ブラウザ表示はチェックリストを使った手動確認を基本とする。
- 公開後に主要ページとGoogle Driveのダウンロードリンクを手動確認する。
- 大規模なブラウザ自動テストは初期段階では導入せず、作品数や機能が増えた段階で再検討する。
